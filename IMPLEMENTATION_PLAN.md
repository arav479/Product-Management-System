# Product Management System: Implementation Plan

This plan turns the current single-screen JavaFX app (which uses hard-coded sample data) into a multi-page app backed by the Oracle database. The work is split between 4 people so that everyone can work in parallel with few merge conflicts.

## Target result

- A **sidebar** with four pages: All Products, Add Product, Update Product, Delete Product.
- **All Products** lists every product from the database and filters it live from a search box.
- **Add Product** is a form with Category and Supplier dropdowns that load from the database.
- **Update Product** lets you pick a product, edit it with the same form, and save.
- **Delete Product** lets you find a product by ID or name, shows its full details read-only, and deletes it after you confirm.
- Every page builds on the backend `Product` class (int IDs, `supplierId`, `categoryId`, `reorderLevel`, `description`). The frontend's sample-data `Product` is removed.

## Shared contract (agree on this on day 1)

The frontend team (P2–P4) codes against these signatures from the start. Until P1's code lands, use a **stub**: a temporary version of `operation` that returns hard-coded lists.

```
// Models (backend, package com.pms)
Category  : int categoryId, String categoryName, toString() -> categoryName
Supplier  : int supplierId, String supplierName, toString() -> supplierName
Product   : existing fields + getReorderLevel()/setReorderLevel()
            + String categoryName, String supplierName (display only, filled by JOIN)

// Data access (backend, class operation)
public static List<Product>  findAll()
public static List<Category> findAllCategories()
public static List<Supplier> findAllSuppliers()
public operation(Product p)
public void add()      // throws SQLException with a readable message on failure
public void update()   // throws SQLException
public void delete()   // throws SQLException
```

**Decision to make on day 1: hard delete or soft delete?** The schema has `STATUS ACTIVE/INACTIVE`. With soft delete, `delete()` sets `STATUS = 'INACTIVE'` and `findAll()` returns only `ACTIVE` rows. Soft delete is recommended because it keeps history.

## P1: Database and backend

**Goal:** a working, tested data layer that the UI can call.

### Database
- [ ] Load `schema.sql` and `insert.sql` into Oracle XE as user `SMARTSTOCK`.
- [ ] Reset the identity counters so new inserts don't reuse seed IDs. Add these lines at the end of `insert.sql`:
  `ALTER TABLE PRODUCT MODIFY PRODUCT_ID GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE);`
  and the same for `SUPPLIER`.
- [ ] `operation.update()` uses an `UPDATED_AT` column that the schema doesn't have. Either add the column to `schema.sql` or remove it from the query.
- [ ] Write a one-page database setup guide (create user, grants, run scripts) and give it to P4 for the README.

### Backend code
- [ ] New `Category` and `Supplier` model classes, as in the contract.
- [ ] `Product`: add `getReorderLevel()`/`setReorderLevel()` and the display-only `categoryName`/`supplierName` fields with getters and setters.
- [ ] Rewrite `add()`: it currently builds SQL but never runs it, has the columns in the wrong order, and breaks on names that contain `'`. Use a `PreparedStatement` with the column names listed and leave out `PRODUCT_ID`.
- [ ] `findAll()`: `PRODUCT` JOIN `CATEGORY` JOIN `SUPPLIER`, ordered by ID, returning only active products if the team picks soft delete.
- [ ] `findAllCategories()` and `findAllSuppliers()`, ordered by name.
- [ ] Make the methods `public`, and have them throw (or return a result) instead of only printing to the console.
- [ ] In `delete()`, turn `ORA-02292` (child record found) into a readable message.
- [ ] Close connections properly (keep the existing try-with-resources pattern).
- [ ] Test it: use `Main` to call every method and print the results.

**Hand-off:** run `mvn install` in `backend/` so the frontend can use the jar, then tell P2.

## P2: App shell, build setup, product list

**Goal:** the app starts, you can move between pages, and the product list shows real data.

### Build
- [ ] In `frontend/pom.xml`, change the Java version from 26 to 17 and set `mainClass` to `com.pms.ProductManagementApp`.
- [ ] Add the `backend` artifact (`com.productmanagement:backend:1.0-SNAPSHOT`) as a dependency.
- [ ] Delete the old frontend use of the sample-data `Product` and `loadSampleData()`.
- [ ] Optional: a parent `pom.xml` at the repo root that lists `backend` and `frontend` as modules.

### Shell (`ProductManagementApp.java`)
- [ ] `BorderPane`: the existing header on top, a sidebar on the left, the active page in the center.
- [ ] Sidebar buttons: All Products, Add Product, Update Product, Delete Product. Highlight the active one with a `nav-active` CSS class.
- [ ] Shared state passed to every page:
  - `ObservableList<Product> products`
  - `ObservableList<Category> categories`
  - `ObservableList<Supplier> suppliers`
  - `refresh()`, which reloads `products` from `findAll()`
  - `showPage(...)` / `openUpdate(Product)`, so other pages can switch to a page (P3 needs this for double-click)
- [ ] Move the helpers (`showAlert`, `button`, `textField`, `formLabel`, column constraints) into `ui/UiUtil.java` so all pages can use them.

### All Products page (`ui/ProductListPage.java`)
- [ ] Move the current table and search box into this page.
- [ ] Columns: ID, Name, Description, Category, Supplier, Price, Quantity, Reorder Level.
- [ ] **Live search**: a listener on the search box's text filters the `FilteredList` on ID, name, category name and supplier name.
- [ ] Optional: a category filter dropdown next to the search box.
- [ ] Highlight rows where `quantity <= reorderLevel` (low stock).
- [ ] Double-click a row to open it on the Update page.
- [ ] Sidebar and low-stock styles in `styles.css`.

**Hand-off:** push the shell early (even with empty pages) so P3 and P4 can plug their pages in.

## P3: Product form, Add and Update pages

**Goal:** you can create and edit products using dropdowns.

### Shared form (`ui/ProductForm.java`)
- [ ] Fields: Name, Description (`TextArea`), Category (`ComboBox<Category>`), Supplier (`ComboBox<Supplier>`), Price, Quantity, Reorder Level (default 5).
- [ ] `setProduct(Product)` fills the form and pre-selects the category and supplier by matching IDs.
- [ ] `readProduct()` validates the input and returns a `Product`, or `null` after showing an error. Rules (from the schema):
  - Name is required, up to 100 characters. Description is up to 500 characters.
  - A category and a supplier must be selected.
  - Price is a number greater than 0. Quantity and reorder level are whole numbers, 0 or more.
- [ ] `clear()` empties the form. Keep the existing trick that brings the prompt text back after a selection is cleared.

### Add page (`ui/AddProductPage.java`)
- [ ] The form with no ID field (the database generates it).
- [ ] Save calls `new operation(p).add()`, shows a success or error message, clears the form and calls `refresh()`.

### Update page (`ui/UpdateProductPage.java`)
- [ ] At the top, P4's `ProductPicker` (use a plain `ComboBox<Product>` until it's ready).
- [ ] Picking a product fills the form.
- [ ] Save calls `update()` and then `refresh()`. Clear disables the form until a product is picked.
- [ ] Support `openUpdate(Product)` from the list page's double-click.

## P4: Delete page, product picker, polish, testing

**Goal:** safe deleting, a reusable search-and-pick component, and a finished, documented app.

### Product picker (`ui/ProductPicker.java`)
- [ ] A reusable control: a text field that filters as you type over ID and name, showing results as "ID – Name".
- [ ] Exposes a `selectedProduct` property. The Update and Delete pages both use it.

### Delete page (`ui/DeleteProductPage.java`)
- [ ] `ProductPicker` at the top.
- [ ] Shows the selected product's details read-only: ID, name, description, category, supplier, price, quantity, reorder level.
- [ ] A Delete button, disabled until a product is selected, then a confirmation dialog ("Delete Laptop (ID 3)?").
- [ ] On Yes: call `delete()`, show the result, call `refresh()` and clear the selection.

### Polish
- [ ] Run database calls off the UI thread with a JavaFX `Task`, so the window doesn't freeze while it waits for Oracle. Show a loading indicator while it runs.
- [ ] Show a clear startup error if the database isn't reachable, instead of crashing.

### Testing and docs
- [ ] Manual test checklist (below). Run it once everything is merged.
- [ ] Update `readme.md`: prerequisites (JDK 17, Oracle XE), database setup (from P1), and how to run (`cd frontend` then `.\mvnw.cmd clean javafx:run`).

## Git workflow
- One branch per person: `feature/backend`, `feature/shell-list`, `feature/add-update`, `feature/delete-polish`.
- Merge to `main` through pull requests. P1 merges first, then P2, then P3 and P4.
- Pull from `main` often, especially after P1's and P2's merges.

## Manual test checklist
- [ ] The app starts and the list shows the seeded products with category and supplier names.
- [ ] Search by part of a name, by ID and by category name. Clearing the search shows all products again.
- [ ] Add a product. It appears in the list with a new ID and no primary-key error.
- [ ] Add with missing fields, a negative price, or text in the quantity field. Each shows an error and nothing is saved.
- [ ] A name that contains an apostrophe (for example, `Kid's Chair`) saves correctly.
- [ ] Update a product's category and supplier. The list shows the change.
- [ ] Delete: cancel leaves the product unchanged. Confirm removes it, or marks it inactive with soft delete.
- [ ] A low-stock product (quantity at or below reorder level) is highlighted.
- [ ] With the database stopped, the app shows a readable error instead of crashing.
